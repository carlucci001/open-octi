The floor everything stands on

The six starter staff

Agents stay off until the model, voice, channel and tool connections they need are set up. A key on its own gives an agent no permission to act.

What happens when an agent wants to do something risky

Agent reaches for a tool

Sending email or SMS, placing a call, taking a payment, deleting a record, paid generation.

The app checks its list

Reading, searching and ordinary record-keeping run on their own. Risky tools must ask. Anything undeclared is refused.

It holds the action

A request is made for that exact call. It works once and expires (15 minutes by default).

You get a notice

Push, email, or both. The approvals panel shows what is waiting.

You say yes or no

Or open a timed window for supervised work. Windows are capped, show a countdown, and can be closed any time.

The agent runs it once

An agent can never approve itself. Only a signed-in administrator can. Every step lands in the audit log.

Settings → Agent Approvals: notice channels, expiry, maximum window, recent activity, and the full list of tools that ask first.

Good to know

It works before you add any AI key

CRM, projects, documents and local knowledge tools run without a provider. One model key switches on text help.

Postiz needs Temporal

Social posting runs through Postiz, and Postiz cannot work without its Temporal service. Docker starts both. A plain Node install must run them separately.

DeerFlow is optional and separate

Start it with docker compose --profile research up -d. It is the upstream service, not the integrated Octi CC research desk.

Hermes is not installed by Docker

Build Board needs a Hermes dashboard and Kanban service you set up yourself. Built-in Hermes support is planned.

Your keys stay in your install

Keys saved in Models & Keys and Stripe setup are stored encrypted in your data volume. Back up that volume before every upgrade.
