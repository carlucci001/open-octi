# OpenOcti 1.2.1

This maintenance release adds enforced separation between private installation data and public release artifacts.

- Export inputs come from an explicit approved list of committed Git files, not a recursive working-folder copy.
- Sample records, configuration examples, and opaque assets must match approved public content hashes.
- Export, build, and publication checks reject private runtime artifacts, credential files, symlinks, disguised databases, and modified release inventories.
- Independent secret scanning cannot be suppressed by repository allowlists or inline comments.
- The public pre-push guard verifies the exact outgoing source and rejects unrelated or intermediate commit histories.
- Public CI checks privacy before installing dependencies. Image publishing requires the successful privacy gate before registry write access.
- Private deployment configuration files are excluded from the public source package.

The checks use synthetic failure cases; no private operating records or credential values are needed for verification. Existing installations retain their own data and credentials.

See [Public release boundary](../guides/public-release-boundary.md) for enforcement details and limits. The functional additions from [1.2.0](1.2.0.md) remain available.
