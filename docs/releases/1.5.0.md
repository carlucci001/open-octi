# OpenOcti 1.5.0

This release carries seven weeks of shared improvements: optional encryption for the credential vault, file attachments and one-click letterhead email in Documents, a permanent pay-online link for invoices, spam and rate protection on the public intake forms, and a long list of voice, agent, media, and finance fixes.

## Credentials

- The credential vault can now be encrypted at rest. Set `FCC_VAULT_KEY` (a base64-encoded random 32-byte key) or point `FCC_VAULT_KEY_FILE` at a protected file, then run `node scripts/encrypt-vault.mjs --dry-run` followed by `--apply`. `--decrypt` reverses the migration. Encryption is optional: an installation without a key keeps working exactly as before.
- The credentials API no longer returns stored secrets in full. List responses are masked, and edits are matched against the stored fields on the server.

## Documents

- Documents can hold real file attachments (PDFs, images, office files) filed in the document's folder. They are stored under `data/document-files` by default; `DOCUMENT_FILES_DIR` overrides the location, and the Docker Compose stack now keeps them inside the `/data` volume.
- One-click **Email to client** sends a document on the installation's letterhead. Agents get the matching `send_document` tool.

## Invoices and payments

- Every invoice has a permanent pay-online link at `/pay/<invoiceId>` on your own domain. It resolves the current checkout session, so the link printed on a quote keeps working after individual provider URLs expire.
- Stripe invoice lifecycle tracking records settlements and payment outcomes inside the datastore transaction, so a concurrent settlement can no longer be overwritten by a stale snapshot.
- Checkout creates a Stripe customer so ACH bank debit is offered, credit top-ups are routed before invoice discovery, and agent-initiated invoice sends are authenticated.
- Agents gained a `create_quote` tool, accept lenient invoice line items, and now see the real error text when an invoice action fails.

## Leads and intake

- The public intake endpoints (website intake, product inquiry) now apply heuristic spam scoring, global, per-client, and per-email rate limits, duplicate-submission detection, and a quarantine that answers spam with a harmless success response.
- Inbound leads from voice and website forms are captured durably with their tenant, brand, and lead-list classification, and the Leads module shows activities in an inline drawer.

## Voice and agents

- Gemini Live remains the voice runtime. Greetings start on time, the login greeting is cached, a dead or ended microphone is recovered or rejected cleanly, wake recognition survives transient network failures and requires an intentional phrase, the header equalizer follows the speaking agent, and agents describe the voice provider that is actually running.
- Groundwork for OpenAI realtime voice sessions ships in this release, but public rosters stay on Gemini Live. No configuration change is needed.
- Agent chat keeps its context across approvals, no longer reports "OpenClaw is reconnecting" on ordinary model timeouts, and the approval gate sits beside the gesture controls in the header.
- Research chat streams require a final receipt before a closed connection counts as complete, so long research answers are not truncated.
- The timer widget follows the server as its source of truth, and the `control_timer` voice tool accepts a client name and asks for one when none is given.

## Domains, media, finance, and labs

- Domain availability and registration use one verified Cloudflare Registrar workflow.
- Media gained Kie unified media jobs and Veo video jobs with no billable retries, and authored media survives SQLite library reconciliation.
- The API spend meter shows OpenAI organization costs and lets you choose per provider whether it counts toward the daily total and alerts.
- API Lab can hold a read-only InMotion OpenStack connection with allocation gauges, and the AI Lab has an NVIDIA GLM-5.3 test route.

## Other fixes

- Ending a video meeting trusts the eject endpoint instead of lagging presence data.
- The feed can clear posts and activity history, and the AI Wizard send button no longer submits stray click events.
- The application image drops the Next.js build cache, and the OpenClaw sidecar image copies only the knowledge files it uses.

## Environment

Four optional variables are new in `.env.example`, all commented out: `DOCUMENT_FILES_DIR`, `OPENCLAW_FIRST_CHUNK_MS`, `FCC_VAULT_KEY`, and `FCC_VAULT_KEY_FILE`.

## Installing and upgrading

Follow the [getting-started guide](../guides/getting-started.md). Back up your existing data and configuration before upgrading. No action is required for existing installations: the credential vault stays unencrypted until you opt in, and attachments are created only when you add them. Docker installations that already set their own `DOCUMENT_FILES_DIR` keep it; otherwise attachments go to `/data/document-files` inside the data volume.

## Verification scope

The exported tree was built and tested before publication, and the Command Center CI now exports, builds, and tests the public tree on every pull request so the two cannot drift again. New automated tests cover the vault encryption (`vaultCrypto`) and the wake-listening indicator (`wakeListeningIndicator`) alongside the existing suite.
