# OpenOcti 1.4.2

This release changes how the owner role is assigned and makes every user-store write transactional.

- Owner status now comes only from the role stored on the user record. A legacy hard-coded owner username rule has been removed, so ownership is always exactly what the stored data says it is.
- If an installation has users but no user is marked owner, exactly one is promoted automatically: the user named by the `FCC_OWNER_USERNAME` environment variable if set, otherwise the earliest-created admin, otherwise the earliest-created user. This promotion is idempotent and only runs when no owner already exists.
- All user-store writes — create, update, suspend, boot, delete, and last-login — are now read-modify-write transactions. Duplicate-username checks and owner-protection checks run inside the same transaction, closing a window where two concurrent writes could race.
- Incident tasks are now assigned to the installation's owner at runtime, using the same stored-role lookup.
- A new environment variable, `FCC_OWNER_USERNAME`, is documented in `.env.example` for installations that want to control which user is promoted to owner.

## Installing and upgrading

Follow the [getting-started guide](../guides/getting-started.md). Back up your existing data and configuration before upgrading. No action is required for existing installations: current owners keep their role, and the owner-promotion logic only runs when a store has users but no owner.

## Verification scope

The owner-role change, the owner-promotion logic, and the transactional user-store writes were covered by new automated tests (`rolesOwnership`, `userStoreConcurrency`) alongside the existing suite. Nothing else changed from 1.4.1.
