# OpenOcti 1.1.2

This security release fixes authentication defaults and hardens webhooks, public agent widgets, URL fetching, agent approvals, email rendering, and agent tool permissions.

## Security fixes

- **OCTI-C-01:** Reject known or weak machine credentials. Generate unique machine secrets automatically on first startup, persist them privately, and share them with the OpenClaw sidecar. Valid environment overrides still take precedence.
- **OCTI-H-02:** Verify Twilio webhook signatures and remove the unauthenticated arbitrary outbound-call callback behavior.
- **OCTI-H-03:** Reject privacy webhook requests when authentication is missing or invalid.
- **OCTI-H-04:** Limit anonymous agent-widget requests to reduce unauthenticated model and voice spending.
- **OCTI-H-05:** Restrict URL-report requests to safe external destinations, validate redirects, and bound response sizes.
- **OCTI-H-06:** Refuse approval-required actions when approval is merely claimed by the model. Approval must come through a trusted human workflow.
- **OCTI-H-07:** Sanitize inbound email HTML before rendering it in the CRM.
- **OCTI-H-09:** Enforce each agent's named-tool allowlist and remove generic dispatch that could bypass it. Existing managed agent configurations are hardened on startup.

The Next.js major-version migration (OCTI-H-08) remains a separate work order; this release does not resolve that dependency finding. Follow the [VPS network guidance](../guides/running-on-a-vps.md).

## Upgrade

Back up the data volume and your protected configuration first. Once the 1.1.2 images are published, Docker installations can upgrade with:

```bash
docker compose pull && docker compose up -d
```

For Node installations:

```bash
git pull && npm ci && npm run build
```

Then restart the Node process with `npm start` or your service manager. Check login, Agents, and configured providers after either upgrade.

Installations exposed to the Internet while running **1.0.0–1.1.1** should rotate their `OPENCLAW_*` machine secrets and review the credentials vault for unexpected access or changes. Rotate provider credentials if exposure is suspected. Do not reuse the old default. New values may be supplied as explicit environment overrides; restart both containers together to apply them.

Without valid overrides, generated values are stored in `CRM_DATA_DIR/openclaw/machine-secrets.json` (`/data/openclaw/machine-secrets.json` in Docker). The file is owned by the app user, uses mode `0600` on Linux, and survives restarts with the volume. Protect its backups as credentials.

Report vulnerabilities privately using the [Security Policy](../../SECURITY.md).
