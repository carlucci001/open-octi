# OpenOcti 1.1.1

OpenOcti 1.1.1 refreshes the public front door and makes the source release easier to install, inspect, and verify.

## What changed

- A task-oriented README with verified feature links, a real 2×3 product gallery, the starter staff, and a clear OpenOcti-versus-Octi-CC boundary.
- Ten short guides for Agents, the Operator rail, Gesture Mode, Command Vault, TruthDiff, Automations, Communications, Labs, Agent Widget, and Ops tools.
- A real 1440×900 screenshot set captured from the OpenOcti edition with isolated SQLite sample data.
- Multi-architecture GHCR workflows for the application and OpenClaw images on `linux/amd64` and `linux/arm64`.
- Compose defaults that pull prebuilt images while retaining `docker compose up -d --build` for source builds.
- Additional public-export exclusions and denylist coverage for private product names, hosts, paths, and seed workspaces.
- An automated Markdown link and image-cap check in the OpenOcti CI path.

## Container availability

The `publish-images.yml` workflow publishes versioned images when a matching version tag is created. The `latest` aliases are published only by the `v1.1.1` tag. Until that tag exists, build from source:

```bash
docker compose up -d --build
```

After the tag is published, upgrade the prebuilt deployment with:

```bash
docker compose pull
docker compose up -d
```

## Compatibility and verification

The compose services keep their existing data volumes and ports. The release export is version-stamped `1.1.1`, scanned for secrets and denied private identifiers, link-checked, tested in both editions, and built independently from the exported tree.
