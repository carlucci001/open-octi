# OpenOcti 1.4.1

This release fixes the first-run experience. A new installation no longer sees Postiz before it has been asked for a workspace name or a model key, and setup no longer leaves the application shell.

- The setup guide shows one next step at a time, in order: name your workspace, add a model key, meet your agents, and only then optional publishing with Postiz. Postiz diagnostics are not fetched until the earlier steps are done, so a fresh installation never sees an unconfigured Postiz status.
- The Ask Octi question box no longer appears before a model key exists. In its place is one line saying that conversational help needs a key.
- Models & Keys opens inside the application, in Settings, from every entry point: the first-run checklist, the setup guide, the avatar menu, and the redirect after the welcome greeting. The standalone `/settings/models` and `/help` pages now redirect into the application; old links keep working.
- Inside the Octi guide, the searchable setup topics are collapsed behind a single "Browse setup topics" control so the guide fits the screen.
- New: a [system map](../guides/system-map.html) ships with the guides. Open it in a browser to see every part of your installation on one screen — the app, the helper services, the outside accounts it can connect to, and the approval gate — with what each part needs and what happens if it stops. Capabilities that belong to Octi CC stay on the map, dimmed, and a switch shows what the commercial edition adds. The same map is live at [openocti.com/system-map](https://openocti.com/system-map).

## Installing and upgrading

Follow the [getting-started guide](../guides/getting-started.md). Back up your existing data and configuration before upgrading. No configuration changes are required for this release.

## Verification scope

The reordered guide, the in-application Models & Keys route, both redirects, and the collapsed topics were covered by the automated suite and checked in a browser against a fresh keyless installation of the full Docker Compose stack, including the bundled Postiz and Gitea services. The system map is a static page with no external requests; it was checked in a browser in both views. Nothing else changed from 1.4.0.
